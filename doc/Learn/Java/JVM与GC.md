# Java JVM 与 GC 系统学习整理笔记

> 目标：**系统理解 JVM、GC、内存模型与核心原理**

---

## 一、IOC 与 AOP

### 1. IOC（Inversion of Control，控制反转）

**一句话理解**：
> 对象的创建和依赖关系，不再由程序员手动控制，而是交给容器（如 Spring）。

#### 核心思想
- 依赖注入（DI）
- 解耦对象之间的依赖

#### 好处
- 降低耦合
- 便于测试（Mock）
- 统一生命周期管理

---

### 2. AOP（Aspect-Oriented Programming，面向切面编程）

**一句话理解**：
> 在不修改业务代码的前提下，为方法统一添加功能。

#### 解决的问题
- 日志
- 事务
- 权限校验
- 性能监控

#### 核心概念
- Aspect（切面）
- Pointcut（切点）
- Advice（通知）
- Join Point（连接点）

---

## 二、并发与并行

### 一句话区分

| 概念 | 说明 |
|----|----|
| 并发 | 同一时间段内处理多件事（逻辑同时） |
| 并行 | 同一时刻真正同时执行（物理同时） |

### 关键点
- 单核 CPU 只能并发，不能并行
- 多线程 ≠ 并行

---

## 三、GC（垃圾回收）基础

### 1. 什么是 GC

**定义**：
> GC 是 JVM 的自动内存管理机制，用于回收不再使用的对象。

### 2. GC 解决的核心问题
1. 哪些对象还活着？
2. 什么时候、如何回收？

### 3. 判断对象是否存活

#### 可达性分析（主流）
- 从 GC Roots 出发
- 不可达对象 = 垃圾

---

## 四、GC Roots

### 1. 什么是 GC Roots

> GC Roots 是可达性分析的起点集合。

### 2. 常见 GC Roots（Java）

- 线程栈中的局部变量
- 活跃线程对象
- 静态变量
- 常量池引用
- JNI 引用
- JVM 内部对象（Class、ClassLoader）

### 3. GC 如何找到 Roots

- 发生在 **Safepoint**
- 通过扫描：
  - 线程栈
  - 方法区
  - 本地方法栈

---

## 五、三色标记算法（Tri-color Marking）

### 1. 三种颜色

| 颜色 | 含义 |
|----|----|
| 白 | 未访问（可能是垃圾） |
| 灰 | 已访问，但引用未扫描完 |
| 黑 | 已访问，引用已扫描完 |

### 2. 核心规则（三色不变式）

> **不允许黑色对象直接引用白色对象**

### 3. 并发 GC 问题

- 用户线程修改引用关系
- 可能导致漏标

### 4. 写屏障

- 强三色不变式（插入写屏障）
- 弱三色不变式（SATB，删除写屏障）

---

## 六、Java 分代设计（Generational GC）

### 1. 设计依据

> 对象“朝生夕死”

### 2. 堆结构

```
Heap
 ├─ Young Generation
 │   ├─ Eden
 │   ├─ Survivor S0
 │   └─ Survivor S1
 └─ Old Generation
```

### 3. 新生代 GC（Minor GC）

- 触发条件：Eden 满
- 算法：复制算法
- 对象在 Survivor 间来回复制

### 4. 对象晋升

- 年龄达到阈值（默认 15）
- Survivor 放不下（提前晋升）
- 大对象直接进入老年代

---

## 七、一次完整的新生代 → 老年代 GC 示例

### 对象生命周期路径

```
创建 → Eden
 → Minor GC → Survivor（来回）
 → 达到阈值 / 放不下
 → Old
 → Full GC
```

### Survivor 放不下怎么办？

- **不会报错**
- 直接提前晋升到老年代
- 若老年代也不足：
  - 触发 Full GC
  - 仍不足 → OOM

---

## 八、Minor GC / Major GC / Full GC

| 类型 | 回收范围 | 是否 STW |
|----|----|----|
| Minor GC | 新生代 | 是（短） |
| Major GC | 老年代 | 是 |
| Full GC | 整堆 + 元空间 | 是（长） |

---

## 九、Full GC = 整堆 + 元空间

### 含义

- 回收：
  - 新生代
  - 老年代
  - **元空间（类卸载）**

### 为什么包含元空间？

- 类也可能变成垃圾
- 只有 Full GC 才会：
  - 扫描 ClassLoader
  - 卸载无用类

---

## 十、符号引用 vs 直接引用

### 1. 符号引用（Symbolic Reference）

- 以名字描述目标
- 与内存地址无关
- 存在于 class 文件、运行时常量池

### 2. 直接引用（Direct Reference）

- 直接指向内存位置
- 运行期存在

### 3. 转换时机

- 类加载的 **解析阶段**
- JVM 支持延迟解析

---

## 十一、永久代（PermGen）与“持久代”

### 1. 永久代（PermGen）

- JDK 8 之前 HotSpot 实现
- 存放类元数据
- 大小固定

### 2. “持久代”

- **非 JVM 官方术语**
- 通常是对 PermGen 的误称

### 3. 元空间（Metaspace）

- JDK 8 引入
- 使用本地内存
- 取代 PermGen

---

## 十二、关键总结

- GC Roots 是可达性分析起点
- 三色标记 + 写屏障保证并发 GC 安全
- 新生代用复制算法，老年代用标记整理
- Survivor 放不下 → 提前晋升
- Full GC = 整堆 + 元空间
- “持久代”不是正式概念

---

## 十三、学习建议

- 能画出对象在 Eden / Survivor / Old 的移动路径
- 能解释一次 Full GC 发生了什么
- 能区分概念 vs 实现（JVM 规范 vs HotSpot）
