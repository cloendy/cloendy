Java 控制台的指令通常指的是 JDK（Java Development Kit）自带的一系列命令行工具，它们覆盖了从**编译、运行**到**监控、诊断**的整个开发与运维生命周期。

### 🛠️ 开发与构建工具
这类是日常开发最基础的工具，用于编写、编译和打包Java程序。

*   **`javac`**：Java编译器，将 `.java` 源代码文件编译成 `.class` 字节码文件。
*   **`java`**：启动Java应用程序，也是设置JVM运行参数（如堆大小 `-Xmx`）的主要入口。
*   **`jar`**：用于创建、查看或解压JAR包，功能类似ZIP工具。
*   **`javadoc`**：从源代码注释中生成HTML格式的API文档。
*   **`javap`**：反编译工具，可以查看`.class`文件对应的字节码指令，用于深入理解代码的底层执行逻辑。
*   **`jshell`**：Java的交互式命令行（REPL），可以像Python一样，无需编写完整类文件就能快速测试代码片段。
*   **`jdeps`**：依赖分析工具，用于分析JAR包或类文件的依赖关系。
*   **`jlink`**：用于组装和优化模块，生成自定义的精简JRE运行时映像（JDK 9+）。

### 📊 监控与诊断工具
这是排查JVM性能问题（如内存泄漏、CPU飙高、死锁）的核心工具集，也是面试和实际工作中最常被问到的部分。

**1. 进程与配置查看**
*   **`jps`**：查看本机java进程信息。快速列出当前系统中所有正在运行的Java进程及其PID，相当于Java版的`ps`命令。常用 `jps -l` 来显示主类全名。
*   **`jinfo`**：查看或动态调整JVM的配置参数/运行时参数（如系统属性、启动参数）。常用 `jinfo -flags <pid>` 来核查启动参数。

**2. 运行时统计与内存分析**
*   **`jstat`**：性能监控工具。实时监控JVM的运行状态统计，特别是**GC情况**和**内存分布**。例如 `jstat -gc <pid> 1000` 可以每秒刷新一次GC数据。
*   **`jmap`**：打印内存映射，制作堆dump文件。用于生成**堆转储快照（Heap Dump）**，是分析内存泄漏的利器。常用 `jmap -dump:format=b,file=heap.hprof <pid>` 导出文件，供MAT等工具分析。

**3. 线程与堆栈分析**
*   **`jstack`**：打印线程的栈信息，制作线程dump文件。生成当前时刻所有Java线程的**栈快照**。这是排查**死锁、线程卡顿**问题的首选工具，通过对比多次快照可以定位问题代码。

**4. “瑞士军刀”诊断工具**
*   **`jcmd`**：一个功能强大的现代诊断工具，可以看作是 `jmap` 和 `jstack` 等功能的集合与增强。例如，`jcmd <pid> Thread.print` 可以打印线程栈，`jcmd <pid> GC.heap_info` 可以查看堆信息。通常建议优先使用它。

**5. 其他**
*   **`jhat`**：已被淘汰的“网页版”堆分析器。本地启动一个 HTTP 服务器，通过浏览器来查看分析结果。JDK 8 中已被标记为废弃（Deprecated），并在 JDK 9 中被彻底移除。
*   **`jvisualvm`**：集监控、故障排查和性能分析于一体的图形化工具。jvisualvm 曾随 JDK 6、7、8 一起捆绑发布。但从 JDK 9 开始，它不再被包含在 JDK 安装包中，需要从 VisualVM 的官方网站单独下载。
  
### 🖥️ 图形化监控与调试
除了命令行，JDK也提供了一些图形化工具，直观性更强。

*   **`jconsole`**：简易的可视化控制台。一个基于JMX的图形化控制台，可以监控JVM的内存、线程、类加载和MBean等状态。
*   **`jdb`**：Java的命令行调试器，可以设置断点、单步执行代码，用于排查复杂的逻辑Bug。
*   **`jmc` (Java Mission Control) & `jfr` (Java Flight Recorder)**：JDK 11+中强大的性能剖析组合。JFR负责在底层记录JVM和应用的详细事件，JMC则提供可视化界面进行分析，适合深入诊断复杂的性能问题。

### 💡 如何获取帮助
几乎所有的JDK工具都支持通过 `--help` 或 `-h` 参数来查看自身的用法和可用选项。例如执行 `javac --help` 或 `jcmd help` 即可获得详细帮助信息。
